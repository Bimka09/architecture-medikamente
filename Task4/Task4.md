# Задание 4. Оценка узких мест при миграции

## 1. Анализ текущей ситуации

Состояние As-Is: Монолит (1С, Excel, файловый сервер). Данные не контролируются, всё вручную, система не масштабируется
Состояние To-Be: Микросервисная архитектура, безопасность данных, отказоустойчивость, масштабируемость под будущий рост, соответствие 152-ФЗ.

Компоненты для миграции:
    - Базы данных: переход от Excel/сканов к связке PostgreSQL + Data Lake
    - Бизнес-логика: Разбить на микросервисы (запись, приём)
    - Коммуникационные каналы: переход от  файлов к API с шифрованием
    - Инфраструктура: замена одного файловый сервер на Kubernetes-кластер

## 3. Возможные проблемы по категориям

| Категория | Проблема | Решение | Приоритет |
|-----------|----------|---------|-----------|
| Персонал | Отсутствие команды разработки и других кадров | Нанять команду DevOps/Backend, обучить, привлечь консультантов | Высокий |
| Процессы | Нет CI/CD | Внедрить GitLab CI/Jenkins, разбить на MVP | Высокий |
| Программное обеспечение | Плохое качество данных | Аудит и очистка, постепенный перенос, ETL-скрипты | Высокий |
| Интеграция | Сложные интеграции | Kafka для буферизации, адаптеры для 1С, тестирование API лабораторий анализов | Высокий |
| Инфраструктура | Отсутствие масштабируемой инфраструктуры | Managed Kubernetes, план DR, мониторинг до запуска | Высокий |
| Процессы | Риск несоответствия 152-ФЗ | Юрист по ИБ, использование Vault, тестирование на безопасноть и проникновение | Критический |
| Персонал | Сопротивление сотрудников | Вовлечь пользователей, обучение, параллельная работа старых и новых систем | Средний |

Приоритетность действий:
    1. Нанять команду разработки и DevOps
    2. Развернуть масштабируемую инфраструктуру с K8s, CI/CD
    3. Организовать работу с данными, прикрутить аудит
    4. Реализовать миграцию согласно плану
    5. Обучать сотрудников

## 4. Рекомендации

### Рекомендации по узким местам:

1) Кадры: 
Команды разработки состоит только админа и техдира, реализовать предстоящие изменения будет сложно. Необходимо донанять персонал или аутсорс
2) Инфраструктура: 
Всё на одном файловом сервере, что подрывает отказоустойчивость. Буде лучше иметь отдельные серверы для медицинских данных и БД 1С
3) Миграция данных: 
Для проведение миграции успешно и в соответсвии с планом следует создать модуль миграции и загружать файлы в нерабочее время
4) Настройка системы: 
Настроить RBAC/ABAC пользователей до запуска

### Рекомендации по компонентам:

Базы данных:
    - Saga-паттерн для распределённых транзакций
    - Redis для кэширования
    - Репликация и мониторинг (Patroni, Prometheus)

Коммуникация:
    - API Gateway
    - Retry и circuit breaker
    - Kafka для асинхронной связи

Инфраструктура:
    - Постепенный перенос в облако
    - Kubernetes + Terraform
    - Логирование (Jaeger, ELK)

Безопасность:
    - Service Mesh (Istio) для шифрования
    - Keycloak для IAM
    - Сканирование уязвимостей (Trivy)
