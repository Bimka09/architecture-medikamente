# Задание 2: Проектирование решения

## Новая архитектура

В рамках новой архитектуры решения Medikamente предлагается выделить следующие компоненты:
1. API Gateway - единая точка входа; аутентификация и авторизация; TLS termination
2. Keycloack для аутентификации - централизованное управление доступом; OAuth 2.1, MFA, RBAC/ABAC
3. Patients Service - персональные данные пациентов и согласия
4. Appointments Service - записи пациентов к врачам
5. Medical Data Service - зашифрованные медицинские данные
8. Сервис аудита - централизованные и неизменяемые логи всех действий (ELK)

Доступ к внутренним ресурсам компании происходить через VPN

Для хранения данных будут использоваться:
- PostgreSQL — операционные данные
- ClickHouse — аналитика и ML


## Построение аналитического слоя

Нужно построить Data Lake со следующими зонами:
- Raw Zone — исходные данные (зашифрованы)
- Trusted Zone — очищенные данные с PII (только для авторизованных)
- Analytics Zone — полностью анонимизированные данные для BI/ML

Процесс сбора данных будет выглядеть следующим образом:
1. Данные попадают в "сырую" зону Data Lake
2. Сервис обезличивания применяет псевдонимизацию, маскирование, агрегацию
3. Обезличенные данные идут в "чистую" зону для BI и ML

Для построения процесса можно использовать следующие инструменты:
- BI: Superset, Metabase, Tableau
- ML: JupyterHub, Kubeflow
- Data Catalog: Apache Atlas/OpenMetadata для тегирования и отслеживания происхождения данных

Для обеспечения безопасности аналитического слоя будут использоваться:
- ABAC для детального управления правами
- Динамическое маскирование в зависимости от роли (например, ФИО → ID для бухгалтерии)
- Добавление статистического шума в отчёты
- Безопасное обучение ML-моделей
